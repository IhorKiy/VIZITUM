# Module Map

Reference for the implemented codebase. Source of truth: `src/modules/*`, `src/app.module.ts`, `src/main.ts`, `src/worker.ts`, `apps/web/app/**`, `apps/web/lib/*`. This describes the current state, not design intent — for design rationale see `docs/vizitum-low-level-technical-design.md`.

When you change a module's responsibility, routes, or key files, update this document in the same change.

## Backend entrypoints

- `src/main.ts` — API server. Applies request-id middleware, access log, CSRF protection, sets global prefix **`/api`**, installs `ApiErrorFilter`. Listens on `HOST`/`PORT` (default `0.0.0.0:4000`).
- `src/worker.ts` — run-to-completion worker process. `WORKER_TASK` selects the task: `cleanup` (deletes expired failed AI jobs and expired temporary storage objects) or `purge` (tenant lifecycle: auto-archives stale `pilot` tenants when `TENANT_PILOT_AUTO_ARCHIVE_DAYS` is set, then permanently deletes archived tenants past `TENANT_PURGE_RETENTION_DAYS` or explicitly marked for purge — `TenantPurgeService`, storage objects first, then rows in explicit dependency order, then the tenant row). Runs to completion and exits. Deployed as a cron, not a long-running queue consumer. (The former `provision` task was removed when tenant creation stopped using `draft`/`provisioning` — see the `platform` module entry below.)
- `src/common/` — `request-id.middleware.ts`, `access-log.middleware.ts`, `api-error.filter.ts` (global error envelope), `json-logger.service.ts`, `sentry.service.ts`, `normalize.ts` (shared `normalizeEmail`), `cookie-token.ts` (cookie name-parameterized read/write/clear, used by both tenant and platform session cookies, and by the CSRF cookie reader), `session-lifecycle.ts` (shared token issuance + TTL/`revokedAt` activity check, used by both tenant and platform sessions, and by `PermissionGuard`'s platform-session branch), `time.ts` (`MILLISECONDS_PER_DAY`, the single source for every day-based TTL calculation).

Note: Redis/BullMQ appear in the LLD and `.env.example`, but no backend code currently consumes `REDIS_URL`. AI transcription/extraction jobs execute in the API process; the worker is a cron cleanup task.

### Tenancy invariant (load-bearing)

Every module touching tenant-owned data reads `tenantId` from `RequestContext` (`request.context`), which `PermissionGuard` builds from the session. Never trust a `tenantId` from a request body, param, or query. Controllers use a local `getRequestContext(request)` helper that throws if the guard did not run.

## Frontend (`apps/web`)

Next.js App Router. All product screens live under the tenant slug: `apps/web/app/[tenantSlug]/...`. Navigation is filtered by session permissions.

**i18n (next-intl, without i18n routing)**: the UI locale is the tenant's `language` setting (`en`/`uk`), not the URL or browser. `proxy.ts` forwards the pathname; `i18n/request.ts` extracts the tenant slug and resolves the locale via the public `GET /tenants/:slug/locale` endpoint (so pre-auth login/invite pages are localized too). Dictionaries live in `apps/web/messages/{en,uk}.json` (namespaces: `common`, `auth`, `invites`, `field`, `manager`, `admin`, `operations`); `en` is canonical and deep-merged under other locales so missing keys fall back to English. `platform/*` and root pages always render in `en`. Every new user-visible string goes through the dictionary — no hardcoded UI literals in `apps/web/app/**` or `components/`.

### Shared frontend libs (`apps/web/lib/`)

- `api-client.ts` — the only path to the backend. Server-side fetch helpers (`apiGet/apiPost/apiPatch/apiDelete`) that forward the incoming cookie header, `x-request-id`, and the CSRF token (read from the `vizitum_csrf` cookie, sent as `x-csrf-token`). Returns `ApiResult<T> = { ok: true; data } | { ok: false; status; message }` — screens branch on `ok`, they do not throw. Also holds the frontend response types. Base URL: `API_BASE_URL` env (default `http://127.0.0.1:4000/api`).
- `navigation.ts` — `buildTenantNav(tenantSlug, permissions)` returns nav items filtered by required permissions (a nav item shows if the user has _any_ of its `requiredPermissions`). Add new screens here with their permission requirements.
- `backend-cookies.ts` — cookie forwarding helpers for server components.
- `demo-mode.ts` — demo data fallback, controlled by `ENABLE_DEMO_FALLBACK` / `NEXT_PUBLIC_ENABLE_DEMO_FALLBACK`; disabled by default in production.
- `tenant-locale.ts` — supported locales (`en`, `uk`), tenant-slug extraction from the pathname and the locale/timezone lookup against `GET /tenants/:slug/locale` (fail-open to `en`/UTC).
- `format.ts` — locale-aware date/enum formatting helpers: `formatDateTime`/`formatShortDate` take a next-intl formatter (honors the tenant timezone), `formatEnumLabel` translates enum-like values via `common.labels.*` with a humanized fallback.

## Tests (`tests/`)

Plain `node --test` + `tsx`, one behavior per file. Groups: `ai-*` (job lifecycle, schemas, draft confirmation, cleanup), `import-*` (CSV/XLSX parsing, validation, templates), `auth-tenant-isolation`, `platform-auth`, `platform-tenant-creation`, `platform-tenant-management`, `users-service`, `tenant-superadmin-*` (admin limit, directional protection, lockout, bootstrap fallback, replacement), `platform-tenant-purge-marking`, `tenant-purge-*` (eligibility, execution order/crash-safety), `tenant-pilot-auto-archive`, `storage-*` (including `storage-tenant-object-purge`), `visit-audio-upload-registration`, `manager-list-filters`, `manual-report-after-ai-failure`, `operations-summary`, `health-readiness`, `json-logger`, `sentry-service`.

Behavior covered by these tests is treated as executable specification. See [executable-spec.md](executable-spec.md) for the product/platform contract map.
